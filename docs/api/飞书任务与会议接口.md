# 飞书任务与会议接口

## 能力边界

Desktop 不再运行 `lark-cli`。Electron 主进程调用 LaunchCrush Server，Server 使用
`FEISHU_USER_ACCESS_TOKEN` 以用户身份只读访问飞书 OpenAPI。

本能力只读取结构化日程与任务，不创建、更新、完成或删除任何飞书数据。

## 飞书权限

应用后台和用户 OAuth 需要包含：

```text
calendar:calendar:readonly
task:task:read
task:tasklist:read
```

`task:tasklist:read` 只用于把任务返回的清单 GUID 补成清单名。缺少它时任务仍返回，
只是 `project_name` 为空并附带 warning。

Server 使用的原生接口：

```text
GET  /open-apis/task/v2/tasks
GET  /open-apis/task/v2/tasklists/{tasklist_guid}
POST /open-apis/calendar/v4/calendars/primary
GET  /open-apis/calendar/v4/calendars/{calendar_id}/events/instance_view
```

任务列表固定查询 `type=my_tasks`、`completed=false`，按 `page_token` 拉取全部页面。

## Server 配置

在被 Git 忽略的 `server/main/xiaozhi-server/data/.env` 中配置：

```dotenv
FEISHU_USER_ACCESS_TOKEN=<user_access_token>
FEISHU_SELF_OPEN_ID=<current_user_open_id>
```

也可使用同名进程环境变量，进程环境变量优先。工作台复用 `morning_brief` 中的
`base_url`、`timezone`、`max_pages` 和 `timeout_seconds`，但不受
`morning_brief.enabled` 开关影响。

Desktop 默认访问 `http://127.0.0.1:8003`，可通过以下环境变量覆盖：

```bash
export DESKPET_SERVER='http://127.0.0.1:8003'
export DESKPET_SERVER_AUTH_TOKEN='<server.auth_key>'
```

## HTTP 接口

Server 开启 `server.auth.enabled` 时，两个接口都必须携带：

```http
Authorization: Bearer <server.auth_key>
```

### 查询状态

```http
GET /xiaozhi/feishu/status
```

返回数据源、用户 open_id、所需权限和配置状态，不返回飞书令牌。

### 查询任务与日程

```http
GET /xiaozhi/feishu/briefing
GET /xiaozhi/feishu/briefing?date=2026-08-19
```

成功响应的 `data`：

```json
{
  "status": {
    "state": "ready",
    "source": "server_openapi",
    "open_id": "ou_xxx",
    "required_scopes": [
      "calendar:calendar:readonly",
      "task:task:read",
      "task:tasklist:read"
    ],
    "missing_scopes": []
  },
  "date": "2026-08-19",
  "meetings": [],
  "tasks": [],
  "warnings": [],
  "fetched_at": "2026-08-19T08:30:00+08:00"
}
```

日历或任务单边失败时仍返回 HTTP 200，并在 `warnings` 和 `missing_scopes` 中说明；
两个主数据源都失败时返回 `502 FEISHU_WORKSPACE_UPSTREAM_ERROR`。未配置用户令牌时
返回 `503 FEISHU_WORKSPACE_NOT_CONFIGURED`。
