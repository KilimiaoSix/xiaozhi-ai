# 基于本人在岗识别的情绪关怀编排设计

日期：2026-08-18

## 目标

在 Server 已有的同帧人体检测与本人核验之上，增加不经过 LLM 的确定性关怀编排：久坐活动提醒、下班安全提醒、21 点与 23 点后的加班提醒，以及随机暖心互动。机器人仍只执行固件已有的表情和预设动作。

## 归属与边界

- 编排放在 `server/`。Server 同时持有 PresenceRegistry 与设备连接，是唯一能安全关联“本人在场”和机器人动作的组件。
- `desktop/` 继续只负责摄像头采集，不保存计时状态，也不直接连接机器人。
- 只有 `effective_state=present` 且 `identity.state=owner` 时才触发个性化关怀。未录入、陌生人、多人的画面均不触发。
- 原始帧、完整关键点和人脸 embedding 不进入关怀模块。模块只读取在岗状态、本人核验结果与三段式水平位置。
- 提醒不经过 LLM，不自动确认任何权限或高风险操作。

## 本人位置

YuNet 已在同一帧输出单人脸边界框。Server/兼容 Agent 将人脸中心横坐标归一化后量化为：

- `< 0.4`：`left`
- `0.4 .. 0.6`：`center`
- `> 0.6`：`right`

位置仅在单人脸 `owner` / `unknown` 状态返回。暖心互动按 `left → look_left`、`right → look_right`、`center/未知 → nod` 选择已有预设动作；动作执行后由固件回中。这里描述的是摄像头画面方向，不推断真实三维方位。

## 规则

### 久坐与喝水

- 本人连续在岗 50 分钟后提醒一次，文案在站立活动与喝水放松之间轮换。
- 本人离开画面不足 5 分钟视为短暂遮挡，不重置连续工作时长。
- 离开满 5 分钟后再次出现，视为完成一次有效休息并重置计时。
- 未离开时每 50 分钟最多提醒一次。

### 下班与加班

- 工作日默认 18:00 下班，17:50 到 18:00 之间本人在场时提醒一次路上注意安全。
- 21:00 到 21:30 之间本人在场时提醒一次早点下班；窗口外不补发。
- 23:00 后本人仍在场时进入强提醒，每 10 分钟最多一次，轮换 `shake` / `roll`，允许 TTS；设备忙时沿用现有逻辑降级为纯提示。
- 每日一次型事件只保存在 Server 内存，不跨进程补发。设备离线时事件直接丢弃，重连后不回放。

### 随机暖心互动

- 默认只在 09:30 到 20:30、本人稳定在场时触发。
- 下一次触发间隔在 45 到 90 分钟之间随机取值，服务重启不会立即触发。
- 高优先级提醒后的 20 分钟内不触发暖心互动。
- 使用 `loving` / `winking` / `confident` 等固件已有表情，并结合本人水平位置选择动作。

## 工位与设备绑定

配置 `wellbeing.bindings` 显式关联 `workstation_id` 和 `device_id`。`device_id` 留空时，仅在当前恰好有一台机器人在线时自动选择；多设备在线时必须显式配置，防止提醒发错设备。

默认绑定桌面端固定工位 `desktop-local`。兼容 `presence-agent` 使用自定义工位时需增加绑定。

## 生命周期与故障语义

- HTTP Server 启动时创建关怀服务后台任务，每 5 秒读取 PresenceRegistry 快照；关闭时取消任务。
- 规则引擎先记录事件已发生，再尝试下发，因此网络失败不会造成下一轮重复轰炸。
- 摄像头断线、状态过期、陌生人出现都按“不确定/不在场”处理；连续 5 分钟后可重置久坐会话。
- 单条推送复用 `push_work_event()`，继续遵守设备忙时 TTS 降级、动作白名单和定时恢复基态。

## 配置与可测试性

所有阈值、时区、工作日、时间窗和绑定都从 `wellbeing` 配置读取。规则引擎注入时间与随机源，单元测试覆盖边界时间、冷却、有效休息、身份过滤、方向动作、离线不回放和服务生命周期。
