# 工伴 macOS 桌面界面设计

## 关联文档

- 实施计划：`../plans/2026-08-18-macos-desktop-ui.md`
- 执行图：`../graphs/2026-08-18-macos-desktop-ui.json`

## 当前状态

`desktop` 目前包含“今天”和“摄像头”两个用户界面。今天页使用深色霓虹实验室风格、大号宣传式标题和大量描边卡片；摄像头页已经接近浅色 macOS 工具，但拥有独立侧栏和另一套视觉变量。两页切换后缺少同一应用的连续感，密集信息也不利于快速扫描。

`server/main/manager-web` 与 `server/main/manager-mobile` 是上游 Server 自带管理端快照，不是工伴桌面产品界面，本次不修改。

## 目标与非目标

### 目标

- 为今天页和摄像头页提供同一套 macOS 桌面应用壳层、导航和视觉语言。
- 保留所有现有业务行为、IPC 调用、状态分支和摄像头持续监测语义。
- 使用紧凑、可扫描的工作台布局替代营销式首屏，覆盖正常、空、加载、禁用、警告和错误状态。
- 使用熟悉的图标、分段控件、开关、列表和分组面板表达操作类型。
- 支持键盘焦点、减少动态效果偏好，并在窗口最小宽度 1080px 下无重叠或截断。

### 非目标

- 不接通 desktop 到 Server 尚未完成的工作事件链路。
- 不修改 Server、固件、飞书或摄像头协议。
- 不新增主题设置页、账号体系或新的业务功能。
- 不修改上游 manager-web / manager-mobile。

## 方案比较

1. **统一 macOS App Shell（采用）**：共享侧栏、标题栏、内容画布和状态区，再分别承载今天与摄像头内容。改动集中在 renderer，视觉一致性最好。
2. **仅重写 CSS**：风险低，但无法解决两页导航重复和结构割裂，也保留无效的摄像头侧栏入口。
3. **完全拆分仪表盘组件**：长期边界最清晰，但会扩大本次重构面并增加行为回归风险，超出纯界面优化所需。

## 视觉系统

- **方向**：macOS Sequoia 风格的桌面工作台。界面是操作工具，不是落地页。
- **字体**：正文与标题使用 `-apple-system` / `BlinkMacSystemFont` / `PingFang SC`；路径、版本和实时指标使用 `SFMono-Regular`。
- **颜色**：系统画布 `#f3f4f6`、内容 `#ffffff`、主文本 `#1d1d1f`、次文本 `#6e6e73`、系统蓝 `#007aff`、成功绿 `#34c759`、提醒橙 `#ff9f0a`、错误红 `#ff3b30`。深色系统偏好使用对应的 macOS 深色材料色。
- **形状**：面板与控件圆角不超过 8px；避免胶囊滥用，只在状态标签中使用完整圆角。
- **层级**：侧栏使用半透明材料；内容区使用浅灰画布和白色分组面板；阴影只区分浮层与主状态区。
- **动效**：仅保留页面淡入、按钮按压和状态点呼吸；`prefers-reduced-motion` 下关闭。
- **图标**：引入 `lucide-react`，按钮和导航统一使用 16–18px 线性图标。

## 布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ macOS traffic lights                                             │
├───────────────┬──────────────────────────────────────────────────┤
│ 工伴          │ 今天 / 摄像头标题                   状态与操作 │
│               ├──────────────────────────────────────────────────┤
│ ▣ 今天        │ 桌面伙伴状态岛                                  │
│ ◉ 摄像头      │                                                  │
│               │ 分组内容：连接 / Agent / 飞书 / 能力 / 事件     │
│               │                                                  │
│ 系统状态      │ 摄像头页：预览 + 录入或监测控制                 │
└───────────────┴──────────────────────────────────────────────────┘
```

侧栏固定 220px；内容区独立滚动。今天页首屏以“桌面伙伴状态岛”汇总 Electron、Server、机器人和 Agent 状态，避免超大标题。Agent 来源使用设置列表式行项目；当前任务和队列保持主次两栏。飞书日程与任务使用并列数据列表。能力与事件位于后续区域，不嵌套卡片。

摄像头页移除自己的重复侧栏，继续保留设备选择、主人录入/实时监测分段控件、画面预览、进度、指标、隐私说明和错误恢复操作。

## 组件边界与数据流

- `AppSidebar`：只负责导航和全局状态展示，通过回调切换页面，不读取 IPC。
- `App`：继续持有全部仪表盘状态与现有 IPC 调用；统一渲染 App Shell，并在内容区切换页面。
- `CameraPage`：继续消费 `CameraMonitoringProvider`，只负责摄像头页面内容，不再拥有全局导航。
- 摄像头子组件：保留现有属性契约，仅增加图标和可访问文本。

业务数据流不变：`window.xiaofei` → React state/provider → 当前组件树。视觉重构不改变 hook 安装、飞书读取、功能触发和摄像头采集行为。

## 异常与边界状态

- Agent/飞书错误继续使用 `role="alert"`，改为 macOS 警告横幅。
- 空任务、空日程、空待办和未启用摄像头均保留明确下一步。
- Server 地址为空时保留断开语义；保存按钮仍调用现有 Gateway。
- 摄像头恢复、Server 重连、注册进行中、注册完成和监测禁用均保留。
- 长路径和长任务标题采用截断并通过 `title` 保留完整值；正文可换行。

## 测试策略

- 为共享侧栏写 DOM 测试，验证导航语义、当前页面状态和回调。
- 运行现有摄像头组件与页面测试，防止监测和录入行为回归。
- 运行 desktop 全量 Vitest、TypeScript 类型检查和 Electron 打包。
- 启动真实 Electron 窗口，检查今天页、摄像头页、滚动、页面切换、分段控件、焦点和窗口内无重叠。

## 风险与回滚

- 主要风险是大范围 CSS 选择器影响现有状态。通过新的 App Shell 命名空间、现有测试和真实窗口截图控制。
- 新增 `lucide-react` 仅用于 renderer 图标，不进入主进程接口。
- 回滚只需恢复 desktop renderer、窗口背景色和依赖清单；没有数据迁移。

## 验收标准

1. 今天页和摄像头页共享同一侧栏与 macOS 视觉变量，切换无重复导航。
2. 所有现有可操作控件仍可用，语义与数据调用不变。
3. 页面覆盖空、加载、禁用、错误、成功和重连状态，文本无重叠。
4. 1080×720 和 1360×880 Electron 窗口下布局可用，内容可滚动。
5. desktop 全量测试、类型检查和打包通过。
6. 无 Git commit。
